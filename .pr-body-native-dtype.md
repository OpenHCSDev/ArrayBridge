## Concrete defect / reproducer

ArrayBridge direct decorators default to PRESERVE_INPUT even when a callable
naturally produces floating measurements. Removing a BaSiC wrapper's own
`astype(input.dtype)` is insufficient: the outer dtype wrapper rescales/casts
its first output. Input uint16 plus output `[-1.25, 12.5, 70000.5]` loses values
unless an explicit native runtime config is passed. OpenHCS pipelines already
default to native via DtypeConfig, but direct calls are a distinct real entrypoint.

## Existing owner extension

`dtype_config_default` accepts the existing DtypeConversionConfig owner. Its
runtime default and reflected signature use the **same object**; explicit
runtime dtype_config still overrides it through existing conversion runners.
No extra policy registry, special BaSiC name dispatch, wrapper bypass, module
global config mutation, fallback or new config schema. Framework/GPU wrapping
and undeclared preserve-input behavior are retained. OpenHCS declares its own
existing DtypeConfig native default on the BaSiC callable.
